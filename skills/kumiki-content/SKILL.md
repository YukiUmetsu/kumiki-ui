# Make a film

Write data, not TSX. Read [the film document](../../docs/component-specs/film-document.md) once. Use the [UI skill](../kumiki-ui/SKILL.md) only if a scene needs a component that does not exist.

1. **Brief.** State one learning objective in one sentence. Get the approved facts, script, assets and their rights. Do not invent numbers, sources or licences. If a fact is missing, ask or mark it as illustrative.
2. **Make it easy to follow.** These come from a [teardown of top short explainers](../../docs/verification/2026-11-06-reference-teardown.md).
   - Put the real numbers or the real thing in the first frame. "Your bill says $120. Your receipt says $100." is clear. "Why do they differ?" is not.
   - Let the viewer guess wrong, then correct them.
   - Show the cause with objects that move and change. Do not list it as text.
   - Keep one subject through the film. Keep it large.
   - Write a caption as 2 to 5 words. A viewer must never read a sentence.
   - Leave no moment fully still. Set `drift` if nothing else moves.
3. **Storyboard.** For each beat of 5 to 9 seconds, write **input → transformation → visible output**. If the beat still explains with the text removed, keep it. Answer the question early. End on the mechanism and its limit, not on a list. Compare two teaching metaphors and pick the one with fewer concepts. [The lessons](../../docs/15-explainer-lessons.md) record why.
4. **Choose scenes.** Map each beat to a recipe with `npm run catalog:find -- --query="<intent>" --format=json`. Read `partialMatches` if there are no results. Use `object-story` when the same objects stay on stage and each phrase changes them. Use a recipe for one intent such as `cause-effect` or `before-after`. Do not use 3D unless the camera or construction needs it.
5. **State the story.** Give scenes a `story`: the first scene `opens` a question, a later scene `closes` it, and at least one scene has a turn (`expects` differs from `actually`). Name the same thing with the same subject ID in each scene. If the checker reports `film-match-available`, use a `match` transition.
6. **Write the file.** Start from `npm run film:example -- --recipe=<id> --out=<dir>`. For exact fields use the schema, or `npm run catalog:api -- --id=<pack> --format=json`. Do not guess fields. Keep one caption per beat, ideally 9 words or fewer. Use `outputs` for each format. Do not crop one format into another.
6b. **Particles follow the same rule.** Name the job first, then `npm run catalog:find -- --type=effect --query="<job>"`, which returns particle kinds and moments with their rules. Give particles a cause (a beam, heat, an impact), keep them countable, and read `compileEffect`'s diagnostics. A particle flow shows direction, not exact values: put the number on a label. See [Environmental Effects](../../docs/component-specs/environmental-effects.md#the-particle-catalog).
6c. **3D shots: pick a recipe by its job.** When a beat needs a real 3D object or place, name the job first (`introduce`, `explain-part`, `construction`, `compare`, `mechanism`, `reveal`, `bridge`, `cause-and-effect`). Then run `npm run catalog:find -- --type=effect --query="<job>"`, which returns the studio, light and splat recipes with their rules. Check each spec with its inspector before rendering: `inspectStudioShot`, `inspectLightShot`, `inspectPhysicsShot`, `inspectFlythrough` or `inspectCapturedPlace`. They refuse text that enters before the camera lands, holds that are too short to read, turns that read as spinning, and captures with no credit. Keep one hero technique per shot, move the camera forward rather than back, and put a CC BY capture's credit on screen. See [Studio Recipes](../../docs/component-specs/studio-recipes.md), [Light Recipes](../../docs/component-specs/light-recipes.md) and Storybook **Video production → Studio Recipes → Choose Recipe By Job**.
6a. **Effects: name the beat, then pick the effect.** Most shots need none. If one does, decide its job first: `mood`, `bridge`, `identity`, `reveal`, `evidence`, `archive` or `living-still`. Then run `npm run catalog:find -- --type=effect --query="<job or beat>"`, which returns the effects and ready-made moments for that job with their rules: what to use them for, what to avoid and the settings. Set `"job"` on every effect: `film:check` refuses a job the effect is not for, and warns when a film breaks studio practice (two effects leading one shot, rays with no light, water that moves the whole picture, dots that lose the picture, a gradient faster than its words, chrome more than once). Read each warning and fix it, or keep it only on purpose. For god rays on a photograph, `npm run fx:light -- <photo> --aspect=16:9` gives `originX` and `originY`. Make the effect resolve into the subject where you can, with `keys`. See [Shader FX](../../docs/component-specs/shader-fx.md#using-each-effect-well) and Storybook **Video production → Shader FX Moments → Choose An Effect**.
7. **Check.** Run `npm run film:check -- <file>`. Fix every error, then run it again. It reports all errors at once and takes about half a second, so use it often.
8. **Review.** Run `npm run film:review -- <file>`. Fix each error. Read each warning: `text-low-contrast`, `frame-mostly-empty` and `focus-off-hero` are measures of the pixels, and each one is usually a real defect. **Open each contact sheet and look at every frame.** Ask: can I read the text in one glance, does each frame have one focus, does the composition fill the frame, and does the picture alone explain the beat? Change the file and run the review again.
9. **Render.** A film with a ray world needs `npm run film:render -- <file> --gl=gpu`. The default draws WebGL in software, which matches on every machine but takes about six times as long. Add `audio.accents` for sound (`npm run film:sound-kit -- <folder> --preset=neutral` makes a kit of designed sounds), tie physical sounds to moments with `audio.cues`, and set `audio.accents.gainDb` to `0`. Lay recorded ambience with `audio.beds`, find sounds with `npm run sound:find`, and set `audio.master` so the mix is checked at render. Run `npm run film:render -- <file>` when the sheets are good, then `npm run video:measure -- <mp4>` for pace and flashes. A 2D film renders at about 4 frames a second, so use the review to test a change.
10. **Report.** State the commands and their results. Report human review as pending. A clean report proves geometry only. You cannot approve your own film.

**Real places.** Look for an openly licensed photograph or footage before you generate a place. Procedural land, caves and water read as computer graphics. Open full-size frames as well as contact sheets, because displacement spikes and blur grids do not show on a sheet. Put a real photograph of the same subject beside your render before you call it realistic. Correct physics does not prove the look: a solved drop still looked like a glass marble until a photograph showed how real drops attach.

**Stop and ask** if an asset has no clear rights, if a claim has no source, or if no recipe fits a beat. Do not change a recipe to fix one film. Fix an authoring rule or a component once, then use it.

**Never:** put exact text or numbers inside generated imagery, add motion that teaches nothing, repeat a title and a caption, or call a film finished before you watch it.
