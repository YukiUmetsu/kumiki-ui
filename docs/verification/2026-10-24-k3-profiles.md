# K3 — three authored profiles for the explanation (2026-10-24)

**Scope:** [19 — Clip-Led Production](../19-clip-led-production-and-revision-handoff.md) §3 K3: the K2 explanation authored independently for 16:9, 9:16 and 1:1, with platform safe areas, protected subjects and chart scales. Built on [K2](2026-10-24-k2-clip-explanation.md).
**Stories:** **Video / Clip Explanation (K2)** — `default` (9:16), `landscape` (16:9), `square` (1:1).
**Code:** [`src/video/clip-explanation-layout.ts`](../../src/video/clip-explanation-layout.ts) (profiles, crop and chart geometry, pure) and [`src/video/clip-explanation.stories.tsx`](../../src/video/clip-explanation.stories.tsx).
**Status:** automated checks, full-resolution exports, and my own frame inspection. **Human review is not done.**

## 1. The three profiles

| Profile | Platform recipe (exporter `--preset`) | Size | Safe area (left / right / top / bottom) | Footage framing | Chart box |
| --- | --- | --- | --- | --- | --- |
| `youtube` (16:9) | `youtube` | 1920×1080 | 8% / 12% / 9% / 10% | native, `cover` | 1536×875 at (154, 97) |
| `youtube-shorts` (9:16) | `youtube-shorts` | 1080×1920 | 8% / 12% / 9% / 19% | `cover`, focus x 0.667 (as K2) | 864×1382 at (86, 173) |
| `social-square` (1:1) | `social-square` | 1080×1080 | 8% / 12% / 9% / 10% | `cover`, focus x 0.5 | 864×875 at (86, 97) |

- Each profile declares its preset in the manifest. The exporter refuses a size mismatch, so a render cannot silently come out at the wrong size.
- The safe-area fractions are the same values as `registry/video/platform-presets.json`; a unit test asserts this.
- The chart is authored at its own box size (not a scaled copy of a full-frame chart), so the text is laid out for the box it sits in.
- The subject track (parcel label and scan line) is shared across profiles. Only the crop changes.

## 2. What the composition does

The same timeline runs in each profile (360 frames, 12 s): a 150-frame scan shot that freezes on the parcel label at 90 (the source frame the freeze resolves to), then a 14-frame dissolve into the 210-frame payoff chart. Labels are the same in every profile; wrapping can differ.

## 4. Frames inspected (my check, not a review)

For each profile I extracted the critical moments: entrance (0), freeze (90), camera travel (120), transition midpoint (157), chart reveal (200, 260), hold (359).

- **Landscape, frame 260:** the chart fits its safe box with legible labels, and the reveal is partway through. The card sits left and top because the platform insets are asymmetric (right 12%, bottom 10%); it is not centred.
- **Square, frame 359:** the full waterfall is visible. The totals read $10 (cost of the miss), −$2 (credit) and $8 (net), and the labels are legible. The same left/top placement shows, with a dark band on the right and bottom.
- **Shorts:** unchanged from K2 in footage framing. The chart now sits inside the 19% bottom inset, so it is smaller than in K2.

## 5. What this does not establish

- **Human visual review** of any profile is not done. Whether the composition is good (centring, weight, pacing) is a judgement I have not certified.
- **Captions:** none are in this composition, so the caption-safety gate is not tested here.
- **Font loading:** each frame re-lays out the chart, and the exporter waits for fonts before every capture. I did not run a case where fonts load late, so "reflow after fonts load" is not demonstrated.
- **Minimum text size** is not checked automatically; legibility was judged by eye at the sizes above.
- **Registry gap found:** `validateFreezeFocus` checks upscaling but not whether a protected subject leaves a `cover` crop. The subject check lives in this composition's layout module (`explanationCropProblems`). Moving it into the registry validator is a follow-up.
- **Synthetic footage and illustrative numbers**, as in K2.
