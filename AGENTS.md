# Kumiki UI — Agent Rules

Read [docs/INDEX.md](docs/INDEX.md), then only the documents relevant to your task. For a quick human-and-agent overview, use the [README capability map](README.md#what-you-can-build) and [agent selection workflow](README.md#for-coding-agents); the map is orientation, **not** an API authority. Before creating new components, **search the installed catalog** with `npm run catalog:find -- --query="your intent" --format=json` (or use `#/catalog` / Storybook **Start here → Component Catalog**). Reuse registered packs and verified Storybook examples when possible. For exact source-backed exports, props and types, use `npm run catalog:api -- --id=COMPONENT --format=json`; do not infer props from catalog search results. Run `npm run catalog:check` after changing registry metadata, semantic kinds or previews. **Do not fabricate components, tests, screenshots, registry availability or browser results.**

## Non-negotiable

1. **Craftsmanship before breadth.** Build one complete component at a time; implement all applicable states, then inspect rendered results. Premium means functioning under stress, not only attractive defaults.
2. **Reusable by anyone.** No consumer- or industry-specific names, business logic, palettes, routes, copy, analytics, or runtime accounts in library code/docs. Demo themes use anonymous identifiers.
3. **Customizable without fragile hacks.** Public APIs expose semantic tokens, documented variants/sizes, appropriate slots/composition, `className`, forwarded DOM props and refs. No app-specific CSS selectors or mandatory globals for a standalone component.
4. **Accessibility is behavior.** Prefer native semantics, Base UI for general composites, React Aria only for justified isolated advanced widgets. Verify keyboard focus, overlays, IME, screen reader behavior and reduced motion.
5. **Design coherence and protected reading space.** Use tokens for typography, spacing, color roles, radii and motion. Avoid tiny text, random gaps, excessive decorative effects and micro-interactions that delay work. Explanatory text must occupy measured, non-overlapping safe regions at the actual output sizes and supported languages. Do not mask scenes with large generic cards, silently truncate explanations, or ship SVG text with unchecked absolute coordinates. Automated rendered-bounds collision checks and screenshot review are mandatory for cinematic/diagram text.
6. **Honest states.** Loading is non-jittery; disabled means non-interactive; errors are actionable; async progress is truthful. Support long and CJK text, zoom, narrow widths and light/dark.
7. **Minimal dependencies.** Install only necessary packages, verify licenses for redistributed code, lock versions, and keep advanced widgets optional.
8. **Registry safety.** Pin releases; review added dependencies and installed paths. Never execute unreviewed external skills/scripts or overwrite consumer customizations silently.
9. **Deterministic constraints before expensive visual QA.** Before producing any explainer, apply the compact [first-attempt lessons](docs/15-explainer-lessons.md): one causal input→transform→output per beat, locked/intentional camera, sparse stable captions, measured chip padding, one Storybook story.  Use [docs/visual-production-contract.md](docs/visual-production-contract.md) and optional `registry/visual/` for required semantic subject framing, safe text regions, event-tied timing, physical attachment ports, and narrative completion. Run CPU-only guards on declared critical scenes; do not substitute pixel/image recognition or LLM reviews for solvable geometry and authoring constraints.
10. **3D visual fidelity is a release gate.** For any 3D subject, scene or cinematic, follow [docs/14-3d-visual-fidelity.md](docs/14-3d-visual-fidelity.md): design physical construction, differentiated PBR surfaces, appropriate texture and detail density, lighting, close-up renders, and explicit stylized exceptions. Primitive-only hero models are WIP, not finished. Run the cheap structural checks and `npm run hero:quality` using [3D evidence rules](docs/verification/hero-quality-gate.md). Record actual human visual review; code checks, screenshot existence and LLM assessments do not certify photorealism.
11. **Evidence required.** A completed component has specs, examples, stories, tests, accessible state coverage, screenshots, visual review and a successful clean registry-install smoke test.
12. **Incremental scope.** Follow [docs/06-roadmap.md](docs/06-roadmap.md). Stop after the requested phase; report exact commands and failures.
13. **Coloured-pencil foundation is mandatory for new art.** Before authoring a coloured-pencil human, animal, landscape, object or science film, study [CP-F1 drawing foundation and artist reference board](docs/research/colour-pencil-foundation-2026-11-14.md). Construct original, named semantic silhouette and local geometry; apply the canonical `createPencilFoundationDrawing` contract with actual reference observations, complete region-to-material mapping, opaque support on solids, form-aligned marks, tonal layers and reviewed frames. `createPencilPhotoStudy` is the CP-F1 route for owned/licensed/public-domain photo-conditioned pencil illustrations. Direct bare CP1/CP2 construction is **legacy compatibility**, not a release-qualified new pencil drawing. No new pencil Storybook folder; keep demos under `Video Production/Film Looks/Colour-pencil`. A passing test is not artist-level reference fidelity.

14. **ArtCraft v7 portrait acceptance is separate from CP-F1.** The legacy code-authored human face failed actual art review in PRs #314/#318/#321 despite valid materials and Playwright screenshots. It is labeled **unapproved experimental construction** in Storybook. Any replacement for the human/portrait style requires a source photo with verified rights, 18 *independently observed* source/actual-render anatomical landmarks, five matched facial value planes, exact image SHA-256 evidence, ArtCraft v7 `portrait_fidelity_gate.py` measured pass, and independent 1×/3× visual review. See [portrait rebuild quality gate](docs/research/colour-pencil-portrait-artcraft-v7-rebuild-gate.md). Passing CP-F1 alone does **not** authorize realistic-art claims, promotion or rigging. Keep unapproved studies explicitly quarantined; no new Storybook folder.

## 3D and visual asset sourcing

Before building complex 3D models, characters, furniture, vehicles, environments, or animations from scratch, read and follow [`docs/ASSET_SOURCING.md`](docs/ASSET_SOURCING.md). Proactively consider high-quality, free-for-commercial-use third-party assets when they save development time or improve visual fidelity. Prefer verified CC0 assets (Poly Haven, ambientCG, verified Kenney packs) for content distributed with Kumiki-UI. Assets from Sketchfab, Poly Pizza, Quaternius, Mixamo, and Fab require item-specific license review: commercial video use does not necessarily permit repackaging source models in a public library or npm package. Preserve provenance, credits, and distribution rights in the asset manifest. If the license is unclear, do not import it; use an alternative or report the blocker. Ensure imported assets meet Kumiki-UI's premium art-direction, optimization, and deterministic animation standards.
